<objective>
Centralize per-engagement Kali working-directory scoping in `ShellManager.execute()` so every command runs inside `/engagements/{engagement_id}/`, satisfying SEC-02. Thread `engagement_id` from each sub-agent's `execute()` into `SSHClient`/`ShellManager` construction, and fix the 4 sub-agent commands that write to absolute `/tmp/...` paths (which a `cd` prefix cannot scope).

Purpose: Stop Kali filesystem artifacts bleeding between concurrent engagements. Isolation is enforced by prefixing `mkdir -p "{workdir}" && cd "{workdir}" && {command}` on every SSH command.
Output: `engagement_id`-aware `SSHClient`/`ShellManager`, 7 sub-agents threading the id, 4 absolute-path command fixes, and a unit test asserting the exact scoped string.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sub-agent command construction → Kali SSH channel | Agent-built command strings cross into the Kali container shell here |
| engagement A filesystem ↔ engagement B filesystem | Shared Kali `/tmp` was the cross-contamination vector; per-engagement workdirs are the new boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Information Disclosure / Tampering | Cross-engagement filesystem bleed via shared Kali `/tmp` and shared output files | mitigate | Centralized `mkdir -p "{workdir}" && cd "{workdir}"` prefix in ShellManager.execute() plus rewriting the 4 absolute `/tmp` output paths to relative — output lands in `/engagements/{engagement_id}/` (SEC-02) |
| T-02-05 | Tampering | The new `cd`/`mkdir` prefix could introduce a shell-injection surface if the workdir string were attacker-controlled | mitigate | `engagement_id` originates from `EngagementSession`, not user input; the workdir is double-quoted in the prefix; no new interpolation of untrusted target data is added by this change |
| T-02-06 | Tampering | Pre-existing unescaped f-string interpolation of `target`/`provider`/`host` into command strings (V5 input validation) | accept | Observed, NOT fixed, explicitly out of scope — SEC-02 requires only workdir scoping; a code comment flags it for a future hardening pass so it is not silently ignored |
</threat_model>
