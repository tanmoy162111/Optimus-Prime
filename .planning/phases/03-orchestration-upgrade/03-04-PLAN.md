<objective>
Build TaskRegistry for real (D-10 — not a stub): the directive-level handoff state store (created/running/completed/failed) that lets OmO detect a directive dispatched but never reported terminal after a crash mid-directive. It lives in the SAME SQLite database and connection as SessionStore (RESEARCH.md Pattern 2) so `task_registry` and `phase_status` writes can be consistent — the only way to make "TaskRegistry disagrees with phase_status after a crash" structurally impossible.

Purpose: PERSIST-01's "trustworthy resume" needs more than a persisted session — it needs to distinguish "directive completed" from "directive was running when the process died." `phase_status` alone can't tell "never started" from "started, never finished"; the `status='running'` crash-detection query (Pattern 2) is that mechanism.
Output: task_registry.py + shared-connection wiring into SessionStore's restart path (exposed as `session_store.task_registry`) + tests.

**Handoff note (resolves the 03-04 ↔ 03-09 ambiguity):** SessionStore owns the single TaskRegistry instance and exposes it as a public attribute `self.task_registry`, constructed once during `initialize()` bound to SessionStore's `self._conn`. Downstream consumers (Plan 09's Orchestrator) read `session_store.task_registry` — they do NOT construct their own. This is the one unambiguous handoff path; there is no alternative "construct-your-own" route.
</objective>

TaskRegistry table (RESEARCH.md Pattern 2 — exact schema):
  CREATE TABLE IF NOT EXISTS task_registry (
    session_id TEXT NOT NULL, directive_id TEXT NOT NULL, agent_name TEXT NOT NULL,
    status TEXT NOT NULL CHECK(status IN ('created','running','completed','failed')),
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL, error_detail TEXT,
    PRIMARY KEY (session_id, directive_id));
  CREATE INDEX IF NOT EXISTS idx_task_registry_session ON task_registry(session_id);

  SELECT directive_id, agent_name FROM task_registry WHERE session_id = ? AND status = 'running'
