<!-- Backend contract (READ-ONLY — frontend conforms to it, does not change it). Verified in RESEARCH.md against backend source. -->
Real path: backend/app.py mounts ws_handler.router with prefix="/ws"; handler is @router.websocket("/chat") ⇒ live path is /ws/chat.
Auth: backend/auth.py verify_ws_token() requires ?token=<bearer_token>; default "dev-token" (backend/config.py, no .env override). Frontend reads import.meta.env.VITE_BEARER_TOKEN || 'dev-token' and appends ?token=<encodeURIComponent(value)>.
Handshake sequence: server sends {type:"welcome"} → client sends {type:"init", session_id:<localStorage or null>} → server replies {type:"session", session_id} → only then client may send {type:"chat", message}. ping/pong heartbeat handled by useWebSocket.
Three payload shapes on this one socket (branch on key presence, NOT a single data.type switch):
  1. Control frames: {type: "welcome"|"session"|"error"|"pong", ...}
  2. Chat-stream fragments: {chunk: "...", done: false|true} — NO type key
  3. Clawhip lifecycle events: {event_type: "PHASE_STARTED"|"PHASE_COMPLETED"|"PHASE_FAILED"|"PLAN_REJECTED"|"GATE_PENDING", directive_id, detail, error} — same socket, via manager.send()
useWebSocket signature (from 04-02): useWebSocket(url, onMessage, enabled = true).
Feature-parity source: frontend/src/App.jsx ChatPanel (lines 1015-1128) + ChatMessage (lines 1129-1179).

<!-- ChatPane's OWN public contract (props this component EXPORTS — consumed by App.jsx in 04-07). -->
ChatPane props: ChatPane({ pendingGate, onGateResolve, onSessionChange, onConnectionChange }).
  - onSessionChange?: (sessionId: string) => void — invoked once with the server-issued session_id at the moment the {type:'session'} ack is received (same moment ChatPane persists it to localStorage). Optional: ChatPane must not crash if the prop is absent.
  - onConnectionChange?: (acked: boolean) => void — invoked with `true` when the session is acked (connected), and `false` on socket close/error (disconnected). This is ChatPane's session-acked status, NOT raw socket-open. Optional.
  - These two callbacks are the ONLY mechanism by which sessionId/chatConnected leave ChatPane. App.jsx (04-07) declares `const [sessionId, setSessionId] = useState(null)` and `const [chatConnected, setChatConnected] = useState(false)` and passes `onSessionChange={setSessionId}` / `onConnectionChange={setChatConnected}`. ChatPane remains self-contained (owns its socket + localStorage); the parent owns the mirrored state per D-08.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-WS-AUTH | Spoofing | ChatPane WebSocket connection | mitigate | Append `?token=<VITE_BEARER_TOKEN||'dev-token'>` (URL-encoded) to the `/ws/chat` URL so the existing server-side `verify_ws_token()` control (ASVS V2) actually takes effect. Without it the server closes every connection with 1008 before `welcome`. Test 1 asserts the token param is present. This phase does not change the auth mechanism itself — it makes the frontend conform to the already-enforced backend control. |
| T-04-02 | Tampering / Elevation of Privilege | ChatMessage / ChatPane rendered content | mitigate | Chat and Clawhip-event content is rendered as JSX text nodes (React default escaping); no `dangerouslySetInnerHTML` is introduced (verified absent in App.jsx today). Both tasks' verify steps grep-assert the sink is absent. |
| T-04-04b | Denial of Service (misrender/crash on unexpected shape) | handleSocketMessage | mitigate | The message router branches on key presence and no-ops on unrecognized `event_type` values, so a `PHASE_FAILED`/`GATE_PENDING` payload cannot crash the handler or render as a malformed blank chat bubble (RESEARCH.md Pitfall 4). Test 5 asserts graceful handling. |
| T-04-03b | Session Management | localStorage session_id | accept | `session_id` is issued/validated server-side (`session_store`) and stored client-side per D-03; single-operator, no multi-tenancy (CLAUDE.md) — no new session-fixation surface since the backend validates/regenerates on `init` (ASVS V3, standard pattern).
