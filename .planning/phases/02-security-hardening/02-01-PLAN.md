<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generated code → sandbox container | LLM-generated, untrusted tool code executes here; the container is the containment boundary |
| backend container → Docker daemon (socket) | The mounted `/var/run/docker.sock` gives the backend host-level Docker control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | run_tool_code() executing untrusted code on the host | mitigate | Execute inside a Docker container with `network_mode="none"`, `mem_limit="256m"`, ephemeral removal — no host process spawned (SEC-01) |
| T-02-02 | Elevation of Privilege | `/var/run/docker.sock` mounted into backend (DooD) grants host-root-equivalent access if backend is compromised | accept | Accepted per locked decision D-10: personal-use single-operator tool (CLAUDE.md); sandbox backend has zero live callers this phase (D-02) so exposure is not exercised; only the trusted first-party `SandboxOnDemandBackend` touches the socket, never the sandboxed generated code |
| T-02-03 | Denial of Service | container.wait timeout leaving a running container (resource leak) | mitigate | On `asyncio.TimeoutError`, explicitly kill + `remove(force=True)` the container; `remove=False` + explicit finally-remove avoids the auto_remove log-capture race (Pitfall 2) |
| T-02-SC | Tampering | `docker==7.2.0` supply-chain (pip install) | mitigate | RESEARCH.md Package Legitimacy Audit verdict `[OK]` / `[VERIFIED: PyPI + official docs]`, disposition Approved — not [ASSUMED]/[SUS], so no blocking legitimacy checkpoint required; exact pin `docker==7.2.0` enforced |
</threat_model>
